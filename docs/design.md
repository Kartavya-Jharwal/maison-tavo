# The custom store makes craft, material and information feel like one experience

The creative target is an award-level kitchenware flagship on Shopify. No award outcome or unverified judging weight is assumed. The complete design programme sits in the [experience roadmap](experience-roadmap.md); this specification sets its review standard.

## References become a coherent art direction

Capture the founder's actual references, the scene worth learning from, and the intended adaptation. Annotate composition, typography, timing, material light, navigation and mobile behavior. Choose a direction through the full password → splash → Home → collection → PDP → cart → Kansa journey, not an isolated hero image.

## Tokens govern rhythm across theme, documentation and marketing

Extend the existing brand contract with primitive, semantic and component tokens for color, typography, fluid scale, spacing, gutters, content width, grid, borders, focus and motion. Generate theme, MkDocs, Kansa and deck outputs. Document purposeful editorial exceptions. Review dense specifications and spacious storytelling together so both read as the same brand.

## Signature interactions explain the object

- A brief, skippable bell/material splash establishes attention and transitions into the hero.
- Scroll-linked cross-sections reveal component order, joinery and food-contact roles.
- A heat-spread toggle is labeled illustrative unless driven by a validated physical model.
- Human / Agent / Voice views expose the same product facts in three forms, preserving variant and focus.
- A finder offers reasoning chips and exclusions rather than an unexplained product score.
- Kansa answers from the same source and returns the visitor to a useful product or care action.

Keep purchase facts and controls usable without these enhancements. Agent views exclude private negotiation floors and personal information. Voice views include readable text; SSML support depends on the actual playback service.

## The finder learns from Made In without inheriting assumptions

Audit Made In's current questions, branching, result explanation and shopping handoff before asserting a five-question flow. Record dated evidence. Proposed Tavo inputs include stove, task, household/service size, budget, existing cookware and maintenance tolerance, with dosa, roti and tadka where relevant. Unknown stove type leads to identification guidance. Structured results and the Kansa fallback use the same rules.

## Three.js earns its place through material comprehension

Use a reviewed object model for rotation, component separation or exterior-to-construction transitions. Start from an art-directed poster. Load the optional bundle when useful, cap rendering cost, pause hidden/offscreen work and dispose resources on teardown. Respect theme-editor section lifecycle, touch, keyboard, reduced motion and context loss.

Motion remains the existing animation foundation. Any additional library needs a clear capability, pinned version, licence, measured payload and owner. Avoid global script loading for a single optional scene. Static fallback must preserve the narrative and shopping route.

## The gate and failures are designed surfaces

The public case study explains the gated store. Password, request-access, forwarded-link and expired-session states remain coherent. Graders receive credentials in the submission note and video. Waitlist forms distinguish an expression of interest from an order or confirmed delivery promise.

Review empty search/cart, missing imagery, unsupported voice, failed network, changed stock and unknown compatibility alongside success states. Check mobile Lighthouse performance ≥80 and accessibility ≥90 plus actual mid-range-phone and throttled-network interaction. Record build and conditions; also check focus, contrast, zoom and reduced motion. Maintain a labeled prerecorded/static demonstration fallback.
